## 1. Présentation & Architecture Générale

### 1.1 Rôle de l'application

**AlcheMix II** est une console de mixage DJ et un atelier de création de mashups, au style
visuel délibérément **steampunk vénitien 1889** (cassettes photoréalistes, galvanomètres,
roue de Camelot). L'interface occupe **tout l'écran, sans barre de défilement** (`h-screen
overflow-hidden`) : tout doit être visible et utilisable d'un coup d'œil.

L'application comprend **deux platines** (Deck A et Deck B) qui jouent chacune une piste audio,
et une **console centrale** qui aide le DJ à les mélanger en harmonie et en rythme.

### 1.2 Les deux moteurs

AlcheMix II repose sur **deux moteurs**, qui communiquent par un **pont IPC**.

- **Backend Rust (Tauri 2)** : lit le fichier audio sur le disque, le **découpe** et l'**analyse**
  (tempo, tonalité, forme d'onde) puis renvoie les résultats au frontend sous forme de données.
- **Frontend SvelteKit (Svelte 5)** : reçoit les données, **joue le son en temps réel** via
  WebAudio, anime les galvanomètres et affiche toute l'interface.

> **IPC (Inter-Process Communication)** : littéralement « communication entre processus ». C'est
> le canal par lequel le frontend (Svelte, côté WebView) et le backend (Rust, côté système)
> s'échangent des commandes et des données. Côté Svelte on appelle `invoke('commande', …)`, côté
> Rust on déclare `#[tauri::command]`. Voir le tableau complet en **section 3.3**.

### 1.3 Schéma global du flux audio

```
  ┌────────────────────────────────── BACKEND RUST (Tauri 2) ──────────────────────────────────┐
  │  Fichier audio sur le disque                                                              │
  │  (MP3, WAV, FLAC, OGG, AIFF)                                                              │
  │        │  Symphonia décode + réduit en MONO 48 kHz                                          │
```

## 2. Spécifications Fonctionnelles — Ce que l'utilisateur peut faire

### 2.1 Les deux platines : Deck A (Émeraude) & Deck B (Bleu)

Chaque platine reproduit une **cassette analogique photoréaliste** (coque, bobines animées,
vis laiton). Les deux platines sont strictement identiques, hormis la couleur du canal :
**Deck A en émeraude (#10b981)** et **Deck B en bleu électrique (#3b82f6 / #00A3FF)**.

| Fonction | Comportement |
|---|---|
| **Chargement** | Bouton **LOAD** (sélecteur de fichiers système, formats LPCM/compressés) ou **glisser-déposer** sur la cassette ; bouton **EJECT** pour décharger. |
| **Transport** | **PLAY**, **PAUSE**, **STOP**, **REW** / **FFWD** (recul/avance rapide de **±20 s**), **CUE** (pause sur repère). |
| **Compteur ROLL** | Horloge de lecture (écoulé / restant), cliquable, chiffres tabulaires. |
| **Galvanomètre VU** | Aiguille balistique **temps réel** alimentée par les échantillons réels du WebAudio (RMS / Peak en dBFS). |
| **Égaliseur 2 bandes** | Filtres **LOW EQ (120 Hz, graves)** et **HIGH EQ (3.2 kHz, aigus)** avec curseurs analogiques. |
| **Faders** | **Volume canal** (gain) et **Pitch** (vitesse, −8 % à +8 %) en fader doré. Le **Volume** est **centré sur 0.0 dB à 50 %** du rail : moitié gauche = atténuation jusqu'à coupure (−∞), moitié droite = boost jusqu'à +6 dB ; clic de la graduation `0 dB` ou double-clic pour recentrer. Chaque rail (LOW/HIGH EQ, Volume, Pitch, Crossfader) porte une **rampe de micro-LEDs** (centre Or `#edbf7a`, émeraude Deck A / bleu Deck B) et des **repères gradués** (micro-étiquettes `tabular-nums`). |
| **Justesse des notes** | Le Pitch change la **vitesse** sans changer la **tonalité** : `preservesPitch = true`. La clé Camelot reste juste. |
| **Métadonnées & pochette** | Titre (fallback nom de fichier), artiste, album, genre, année, **BPM tagué** et **clé taguée** extraits des tags du fichier via **`lofty`** (ID3v2.3/v2.4, Vorbis, MP4, FLAC, WAV). Genre : index numériques ID3v1 convertis en libellé texte (17 ⇒ Rock, 18 ⇒ Techno…) ; clé taguée normalisée **Camelot 1A–12B**. **Aucune valeur de test** : si un tag est réellement absent, l'interface affiche un tiret discret « — ». Enrichissement complémentaire via **MusicBrainz** et **Cover Art Archive** (+ pochette extraite du fichier ou API musicale en fallback). |
| **Télémétrie Rythme & Clé** | Bloc bas de platine : BPM effectif, clé Camelot + mode, clé standard — aux couleurs du canal. |

### 2.2 La Console Centrale — Roue de Camelot & Oracle Acoustique

La console centrale (au milieu) est le cerveau du mixage.

- **Roue de Camelot** : cercle des quintes en notation **1A–12B** (voir encadré). Deux **aiguilles**
  (Émeraude = Deck A, Bleu = Deck B) pointent la clé de chaque piste ; une **aiguille dorée**
  centrale matérialise la modulation.
- **Affinité harmonique** : un pourcentage d'affinité entre les deux pistes est calculé selon la
  proximité sur la roue. Deux pistes compatibles partagent des accords communs et se mélangent
  sans dissonance.
- **Oracle Acoustique** : propose des **conseils de mixage chiffrés** (fréquences en Hz, gains en
  dB, écarts en BPM, en mesures) pour réussir un enchaînement.
- **Pont de clé (Bridge Finder)** : recherche via **Deezer** les pistes « ponts » permettant de
  passer progressivement d'une clé à l'autre, avec **pré-écoute 30 s**.
- **Crossfader Master** : glissière centrale de transition **à puissance égale** entre les deux
  canaux (gauche = 100 % Deck A, droite = 100 % Deck B, au milieu 50/50 sans coupure de volume).
  Sa **rampe de micro-LEDs** éclaire en émeraude vers Deck A, en bleu électrique vers Deck B, et
  en **Or `50/50`** au centre.

> **Clé Camelot (notation 1A–12B)** : un classement des tonalités sur un cercle de 24 cases
> (12 numéros × modes A mineur / B majeur). Deux pistes « voisines » sur la roue se mélangent
> bien ; c'est un repère visuel immédiat pour le DJ.
>
> **BPM (Battements Par Minute)** : mesure du tempo, c.-à-d. le nombre de temps (battements) par
> minute. Un morceau à 120 BPM a deux battements par seconde.

### 2.3 L'Atelier Beatgrid & Mashup

Onglet central dédié à la synchronisation fine et au mashup de deux pistes.

- **Double forme d'onde superposée** : la piste A (émeraude) et la piste B (bleu) s'affichent en
  parallèle, autour d'une **aiguille dorée centrale** qui marque le temps de lecture.
  - Rendu **Canvas 2D 60 fps** haute densité en **waveform miroir haute définition** : barres fines
    (2 px de large, ~1 px d'écart) **symétriques autour de l'axe horizontal central**, avec contraste
    dynamique (`Math.pow` 1.5) pour faire ressortir chaque kick et pause. **3 couches de l'intérieur
    vers l'extérieur** : Basses **cuivre** au centre, Voix/Mélodie **émeraude (A) / bleu (B)** au
    milieu, Aigus **or clair** aux pointes. Les ondes sont **agrandies (200 px)** et les pistes
    télémétriques à **60 px** ; scaling `devicePixelRatio` auto. Légende des couleurs en **haut du
    cadre** : *Cuivre : Basses • Vert/Bleu : Voix & Mélodie • Or : Aigus*.
- **2 pistes télémétriques dédiées** (sous les ondes principales) : deux bandes compactes (~60 px),
  émeraude Platine A / bleu Platine B, traversées par la même aiguille dorée et synchronisées sur le
  zoom (4/8/16 MES) et `elapsedSeconds`. Elles affichent l'analyse selon le **calque choisi** :
  - **TEMPO** : courbe lumineuse de l'évolution du **tempo local** (normalisé dans l'octave du BPM
    global de la platine, `0.75× ≤ local ≤ 1.35×` — supprime les faux 240 BPM) + **valeur BPM
    instantanée** et **halo ambré** là où la dérive dépasse **±0.5 BPM** par rapport au tempo moyen.
  - **CLÉS** : **blocs segmentés de clés Camelot** (2A, 8A, 4B…) par phrase musicale, avec
    **surlignage cuivré** en cas de **clash** harmonique entre A et B.
- Sélecteur **CALQUE [ TEMPO | CLÉS ]** dans la barre d'outils pour basculer d'un calque à l'autre.
- **Repères de phrasé** : les traits dorés (toutes les 4 mesures) portent leur **numéro de mesure**
  (M1, M5, M9…) en haut ; la lecture est indiquée par **◄ Passé / À venir ►** de part et d'autre de
  l'aiguille centrale.
- **Vocabulaire starter-friendly** : cartes **Platine A • Maître / Platine B • Synchro**, bouton
  **Caler Temps 1** (ancrage du temps 1), bandeau **Conseil** d'action contextuel en 1 ligne.
- **Vérité de synchronisation** : le statut n'affiche **RYTHME VERROUILLÉ ✓** que si **les 2 platines
  sont chargées** **et** que leur **tempo effectif est aligné (`|ΔBPM| ≤ 0.2`)** ; sinon **TEMPOS
  NON ALIGNÉS** en ambre. L'infobulle donne l'écart en ms / les BPM effectifs.
- **Vernier de phase** : réglage fin du décalage temporel (ms) avec pourcentage de verrouillage.
- **Édition de grille** : **Caler Temps 1** (poser le temps 1), **décalage fin ±10 ms**, correcteur
  d'octave **÷2 / ×2** (demi-tempo / double-tempo). Le canvas est redessiné **immédiatement** (60 fps,
  même tick) et l'**offset courant** (`+0 ms` / `+15 ms`) est affiché juste à droite de **×2**.
- **Cible d'édition GRILLE : PLATINE A | PLATINE B** (ALC-162) : libellés unifiés (au lieu de
  « Tape A/Tape B ») ; la **waveform ciblée est illuminée** — bordure émeraude (`#10b981`) + halo Platine A,
  ou bordure bleue (`#38bdf8`) + halo Platine B — avec un badge discret **CIBLE GRILLE**. Un **clic sur le
  cadre d'une onde (ou la touche Entrée/Espace)** bascule la cible d'édition sur cette platine.
- **Auto-Loop Roll quantifié** : boucle de **1/2 à 16 temps**, parfaitement calée sur la grille
  (`T_beat = 60 / BPM`), avec marqueurs **▲ IN / OUT ▲**.
- **4 Hot Cues par platine** : repères instantanés **INTRO, DROP, ACAP, OUTRO**, **dédoublés
  visuellement par piste** (Tape A émeraude / Tape B bleu). Poser un repère puis cliquer pour
  rappeler la position dans la piste.
- **ALIGNER TEMPO & PHASE** : cale automatiquement le Deck B sur le Deck A (pitch + position).
- **▶ LANCER A + B / ⏸ PAUSE A + B** (ALC-161) : à droite d'« Aligner Tempo & Phase », un **bouton
  doré** lance **simultanément les deux platines** dans le même tick (positions + `transport`
  synchrones dérivées de `setTransport`/`startPlayer` des decks). Si les tempos/phases ne sont pas
  encore alignés, l'alignement automatique de B sur A est exécuté d'abord ; les positions de départ
  (`startPosA`, `startPosB`) sont mémorisées pour le rappel. Le même bouton bascule en
  **⏸ PAUSE A + B** quand les deux platines jouent.
- **↺ RETOUR CALAGE** (ALC-161) : bouton compact qui met en pause (ou repositionne à la volée) les
  deux platines sur `(startPosA, startPosB)` pour **re-tester la transition en un clic**, autant de
  fois que souhaité.
- **Assistant de transition** (BridgeSuggester) : bandeau d'alerte harmonique + **Smart Filter**
  qui atténue automatiquement les graves/médiums en cas d'incompatibilité de clé pendant le mix.
- **Cartes comparatives** : résumé compact « Tape A • Pivot / Tape B • Récepteur » (BPM, clé),
  positionnées en une rangée dense pour ne pas gaspiller d'espace vertical.
- **Pupitre horloger (ALC-230)** : les boutons du bas sont des **touches mécaniques `VzKey`** à trois
  gabarits — **hero** (la promesse 1-clic : `AUTO-MASHUP 1‑CLIC`, unique à l'écran, avec barre de
  progression `ÉTAPE i/5` + `Annuler` pendant le pipeline et pulse LED « prêt »), **secondary**
  (actions principales : `ALIGNER TEMPO & PHASE`, `LANCER/PAUSE A+B`), **ghost** (actions secondaires
  : `RETOUR CALAGE`, `RESET STEMS`, `AUTO VOIX`, `INST → VOIX`, `RELAIS`). Le **transport** est une
  seule touche à verrouillage **▶ LANCER A + B ⇄ ⏸ PAUSE A + B** (LED or allumée en lecture,
  `aria-pressed`) ; plus aucune touche rouge hors enregistrement. Mise en page **12 colonnes
  alignées** (les deux moitiés partagent les mêmes bordures, aucune rangée ne finit en drapeau) :
  ROW1 **HOT CUES A | B** en pads composés (LED+nom+`mm:ss` tabular + ▶ 32 px couleur canal, états
  vide / posé / rappelé-en lecture), ROW2 **LOOP A/B·TEMPS**, puis les groupes **01 PRÉPARER /
  02 JOUER / 03 MASHUP 1‑CLIC** séparés par des règles gravées. Chaque touche expose **hover,
  enfoncement, verrouillage (LED 6 px), focus clavier et désactivation avec raison** (`title` +
  `aria-describedby`) ; tant qu'une platine manque, l'en-tête du groupe affiche **« REQUIERT A + B »**.
- **Profil OST / Cinéma (ALC-231)** : la micro-bascule **`[CLUB | OST]`** du groupe `03 MASHUP 1‑CLIC`
  choisit le style d'alignement du mashup automatique. En mode **OST**, l'AUTO-MASHUP 1‑CLIC associe
  une **bande originale instrumentale** (James Bond, Hans Zimmer…) à un **vocal pop/ballade** par
  **ancrage de climax** : l'algorithme `computeOstVocalMashupPlan` repère la zone calme de l'OST
  (piano/cordes), son climax orchestral (percussions épiques/cuivres), le couplet et le refrain du
  vocal, puis **rétro-cale l'entrée du vocal** pour que son refrain tombe sur le climax
  (`ostEntrySeconds = max(calmStart, climax − (chorus − verse))`, quantifié au temps fort) ; un repère
  doré **`▼ CLIMAX OST`** s'affiche sur la forme d'onde instrumentale. Pendant la lecture, le
  **Dynamic Orchestral Ducking** creuse un filtre `peaking` à **1 800 Hz** (jusqu'à **−4.5 dB**) sur
  l'OST au rythme des phrases chantées du vocal, puis restitue l'ampleur des cordes entre les phrases.
  Le profil bascule **automatiquement** en `OST` quand l'énergie vocale de la platine instrumentale
  est < 5 % (piste quasi purement instrumentale) ; un tampon `h-screen overflow-hidden` est conservé.
  **Détection automatique par genre (ALC-233)** : si le genre de la platine porteuse contient
  `ost`, `cinéma`/`cinema`, `soundtrack` ou `score` (insensible à la casse, détection « par mot »
  sans faux positifs type `Ghost`), le profil bascule automatiquement en `OST` au chargement d'une
  piste, à l'édition de ses tags ou au lancement de l'AUTO-MASHUP. Le DJ conserve toujours la main :
  chaque clic sur la bascule `[CLUB | OST]` force manuellement le profil (verrou `ostProfileManual`),
  prioritaire sur l'auto-détection tant qu'une nouvelle piste n'est pas chargée ; l'infobulle du
  bouton indique « détecté automatiquement par le genre » ou « choix manuel ».
  **Repères visuels & équilibre vertical (ALC-231)** : rubans waveform A/B réduits à **~115 px** et
  sous-courbes télémétriques à **~44 px** (padding du pupitre resserré) pour que le groupe
  `03 MASHUP 1‑CLIC` (hero `AUTO‑MASHUP 1‑CLIC`, `RECETTE`, `[CLUB | OST]`) soit **100 % visible**
  au-dessus du Crossfader Master (`h-screen overflow-hidden`, rubans toujours ≥ 110 px). En profil
  OST, l'en-tête du ruban porteur affiche le badge ambré **`PROFIL OST • ANCRAGE CLIMAX`**
  (+ **`DUCKING ORCHESTRAL 1.8 kHz ACTIF`** pendant la lecture) et la waveform dessine **`▼ ENTRÉE
  VOIX`** (`ostEntrySeconds`) et **`★ CLIMAX OST`** (`climaxSeconds`), reliés par une **zone ambrée**
  matérialisant la montée orchestrale jusqu'au climax ; le bandeau central affiche un chip
  **`PROFIL OST`**. Alias API `isOstGenre = genreHintsOstCinema` (détection de genre OST).
- **Mode Chef d'Orchestre — partitions d'arrangement JSON (ALC-269)** : dans le groupe `03 MASHUP 1‑CLIC`, le
  bouton compact **`content_paste` COLLER PARTITION** lit `navigator.clipboard.readText()` (ou un mini
  champ texte de repli si WebView2 refuse) et charge une **`MashupArrangementScore`** ; une cartouche
  horlogère dorée affiche `score.title`, le repère actif et les commandes **`play_arrow` EXÉCUTER /
  `stop` ARRÊTER / `close`**. `launchArrangementScore` verrouille le tempo maître en octave normalisée
  (`effectiveBpmA === effectiveBpmB`, `preservesPitch`), applique les rôles EQ/ducking de `score.eq`,
  calcule les positions de départ quantifiées sur la grille réelle (`drums.wav` / `firstDownbeatSeconds`,
  `deckA.startBar` / `deckB.entryBar`) puis **démarre les deux platines simultanément** dans le geste
  utilisateur ; une boucle `requestAnimationFrame` (60 fps) convertit la position maîtresse en
  `currentBar` et applique les changements de stems en fondu doux (`setTargetAtTime`, 40–60 ms,
  `syncStemMediaState`). Sur les rubans waveform, chaque repère de la timeline est dessiné comme un
  **trait doré à la mesure `cue.bar`** avec une cartouche compacte **`M{bar} • {label}`**. Tout geste
  manuel du DJ (mute/gain/solo/crossfader) interrompt l'automatisation sans couper l'audio.
- **IA Chef d'Orchestre embarquée (ALC-270)** : 100 % hors-ligne — un modèle de langage local optionnel
  (~1,9 Go, `qwen2.5-coder-3b-instruct-q4_k_m.gguf`) téléchargé **une seule fois** au choix explicite de
  l'utilisateur (installateur NSIS décoché par défaut, ou modale `ChefAiInstallModal` au premier lancement
  si `optInState === 'unset'`). La génération interroge `library.db` (`mashup_rules` actives + **2 partitions
  `arrangement_scores` les plus proches** = apprentissage contextuel immédiat) et produit un JSON
  `MashupArrangementScore` prêt pour `parseAndValidateArrangementScore`. Le **bouton `auto_awesome` GÉNÉRER IA**
  du Beatgrid l'importe en un clic ; `bookmark_add` SAUVER enregistre la partition notée (1..5 étoiles) pour
  l'apprentissage continu ; `dataset` EXPORT LORA (.JSONL) dans la Librairie exporte le jeu d'entraînement
  (`rating >= 4`).
  **Phrase-Synced Vocal Slicing — OST 1.0x (ALC-237)** : en profil OST, le mixage **ne modifie plus
  aucun tempo** — l'OST ET le vocal jouent à leur `playbackRate` **1.000** (bande originale 131.2 BPM,
  voix 122.6 BPM → timbre et clé **100 % préservés**, fin de la voix accélérée / +1,17 demi-ton de
  *How Deep Is Your Love* 122.6→131.2, et plus aucun étirement de la nappe orchestrale). La **dérive
  rythmique** (~7 % entre 122.6 et 131.2 BPM) est absorbée en **découpant le vocal strophe par
  strophe** (`extractVocalStanzas`) et en **recalant chaque strophe sur un temps fort (downbeat) de
  l'OST** jouée à 1.0x : `computePhraseSyncedVocalPlan` produit `slices [{ airSeconds,
  vocalFileSeconds }]` avec `airSeconds` **quantifié sur la grille** `60/131.2` s (et `gridOffsetMs`),
  et le store **re-seeke le lecteur vocal à chaque frontière de phrase** (`startPhraseSyncSlicing`,
  rAF 60 fps, arrêt propre sur pause/stop) — le silence de respiration entre les strophes sert de
  tampon, sans aucun `detune` ni `playbackRate ≠ 1`. Le déclenchement du vocal reste synchronisé en
  temps réel (`target = ostEntrySeconds`, temps réel = temps fichier à 1.0x). Le plan
  `computeOstMashupTempo` (ex-« l'OST glisse vers le vocal ») reste exposé comme utilitaire pur testé
  mais n'est **plus appliqué** au pipeline. Les stems joués hors `1.000` (mode Club / fader CADENCE)
  bénéficient du **Key Lock naïf** (compensation `detune = −1200·log2(rate)` en cents, toggle
  `keyLock` exposé en télémétrie), et le **ducking orchestral est plafonné à −3.0 dB à 1 800 Hz**
  (`updateDynamicOrchestralDucking`, ALC-248-2) — les cuivres, cordes et guitares de l'instrumental
  restent pleins même en présence de dialogue résiduel (fini l'étouffement à −6.5 dB qui creusait
  l'arrangement).
  **Quantification vocale fine & respiration orchestrale (ALC-238)** : `extractVocalStanzas`
  abaisse la respiration inter-phrases à **0.22 s** (`minPauseSeconds`, repli 1 bin) ;
  `computePhraseSyncedVocalPlan` **subdivise** toute strophe au-delà de **4 mesures** en
  sous-tranches de **2 ou 4 mesures** quantifiées sur les downbeats de l'OST (palier 2 mesures si
  la dérive d'une tranche de 4 mesures dépasserait ~150 ms, `maxSliceDriftSeconds` exposé) et
  enrichit chaque `slice` de **`vocalEndSeconds`** et **`mutedWindow`**. Les **Orchestral
  Breathing Windows** (`breathingWindows [{ startSeconds, endSeconds, reason: 'intro' |
  'dialogue' | 'theme' }]`) coupent la voix sur l'**intro orchestrale** avant l'entrée du vocal,
  sur les **dialogues résiduels** de l'OST (stem `vocals` > 0.22) et sur les **thèmes
  cuivres/percussions solo** (fenêtres de 4 mesures post-refrain où le stem `other` dépasse
  0.88 × son pic global). `startPhraseSyncSlicing` applique un **fondu SORTIE 30 ms** à l'entrée
  d'une respiration / fin de strophe et un **fondu ENTREE 15 ms** pile au seek sur le temps fort
  (anti-clic 15 ms avant chaque seek) ; la réouverture respecte mutes/volumes effectifs.
  `BeatgridView.svelte` affiche les tranches en **cartouches `PHRASE N`** (repères dorés verticaux
  sur chaque `airSeconds`) et les respirations en **zones hachurées ambrées** `THÈME OST SOLO` /
  `DIALOGUE` / `INTRO`.
  **Couverture intégrale des dialogues/breaks OST (ALC-239)** : le seuil de détection des
  dialogues résiduels de l'OST passe de **0.22 à 0.12** ; les **breaks cinématographiques** sont
  en plus repérés par la **chute de batterie** (`ostStems.drums` < 0.20 × pic après l'entrée du
  premier drop > 0.50 × pic, tant que `other` ou `vocals` reste actif). Chaque fenêtre
  `mutedWindow` (hors intro, jamais étendue pour ne pas couper l'entrée vocale) est **étendue d'1
  mesure avant et 1 mesure après** (fin quantifiée au downbeat suivant), et les fenêtres distantes
  de moins de **4 mesures** sont **fusionnées en un bloc `THÈME OST SOLO` continu** — plus aucun
  chant ne coupe ni ne redémarre au milieu d'une phrase parlée (le break 02:35–02:55 de *James
  Bond 007 Theme Remix* est désormais entièrement couvert). À la sortie d'un `mutedWindow`, la voix
  ne se rouvre (fade 15 ms) **qu'au franchissement exact du `airSeconds` de la tranche suivante**
  (downbeat post-break, jamais en pleine fenêtre). **Progression vocale anti-stutter & auto-OST
  (ALC-245)** : le plan Phrase-Synced garantit des `vocalFileSeconds` **strictement croissants**
  (curseur `lastVocalCursorSeconds`, jamais de répétition de phrase en boucle) et se **ferme en fin
  de contenu chanté** — l'OST termine en solo instrumental ; la bascule **`[CLUB | OST]`** s'active
  automatiquement dès qu'une platine porte un genre de bande originale (`ost`, `cinéma`, `cinema`,
  `soundtrack`, `score`) au chargement, à l'édition des tags ou à l'ouverture du Beatgrid (sauf
  verrou manuel « club »).
  **Mashup OST continu Beatmatch + Key-Lock natif (ALC-246/247)** : depuis ALC-246, le profil OST
  joue en **lecture continue verrouillée** — l'OST reste à **1.0x**, le stem vocal est plié à
  `vocalPlaybackRate = cible/voix` (octave `[0.75..1.35]`) ; **ALC-252 : moteur stems EXCLUSIF
  `AudioBufferSourceNode` échantillon-précis** (les 4 `AudioBuffer` démarrent au même `startAt =
  ctx.currentTime + 0.015`, connectés à leurs `stemGainNodes` → EQ `lowFilter→highFilter→
  channelGain→analyser→destination` ; le **Key Lock** est assuré par `detune = −1200·log2(rate)`
  cents) — le moteur `<audio>/createMediaElementSource` a été **abandonné** (WebView2 bloque
  silencieusement plusieurs des 8 balises simultanées → stems muets) → `deckA.effectiveBpm ===
  deckB.effectiveBpm` de bout en bout, **zéro découpage haché et zéro re-seek périodique** ;
  `computeContinuousOstMashupPlan` fixe `ostEntrySeconds` et `vocalStartSeconds` sur des **downbeats
  de 4 mesures** et expose des `breathingWindows` **macro ≥ 8 mesures** (INTRO / DIALOGUE / THÈME OST
  SOLO) pendant lesquelles seul le gain vocal est fondu **180 ms** (`startOstBreathingFader`), jamais
  un seek ; ALC-247 garantit qu'un **drop actif** (`drums ≥ 0.35 × pic`) laisse toujours chanter le
  vocal (aucune fenêtre THÈME) et plafonne fenêtres et fusions à **8 mesures**. **Correctifs lecture
  vidéo (ALC-248)** — *zéro double voix* : `setStemVolume`/`setStemGain` forcent aussi
  `el.muted` sur l'élément `<audio>` dédié dès `gain == 0` (et l'unmutent dès `> 0`), en plus du
  GainNode Web Audio ; `playStems`/`seek` posent `el.currentTime = offset` sur les **4 éléments
  avant** le `Promise.all(el.play())` et le recalage de dérive inter-stems passe de 12 ms à **5 ms**.
  *Intégrité de l'instrumental* : au lancement, tout élément non muté resté `paused`/en erreur est
  **relancé** et l'état réel des 4 stems est logué (`[STEMS-DEBUG]`) ; le **Dynamic Orchestral
  Ducking** est plafonné à **−3.0 dB** (ci-dessus). *Longs ponts instrumentaux* : si le stem vocal
  contient un **pont vide ≥ 8 mesures** après le premier couplet/refrain, le plan émet
  `vocalBridgeSkips [{ triggerOstSeconds, jumpToVocalSeconds }]` (déclencheur quantifié au downbeat de
  4 mesures de l'OST, saut au downbeat de 4 mesures du couplet suivant) — le fader applique un
  **fondu 40 ms** puis avance le vocal au prochain bloc chanté (fini les ~45 s de silence). *Phase
  protégée* : pendant un **AUTO-MASHUP actif**, un clic sur `ALIGNER TEMPO & PHASE` **conserve
  l'offset d'alignement vocal** (`deckB = deckA.elapsed − ostEntrySeconds + vocalStartSeconds`) au
  lieu de remettre le deck B à `00:00`. **Zéro silence au déclenchement (ALC-249)** : chaque
  `playStems`/`seek`/`setStemVolume`/`setStemGain` **ré-synchronise l'état média** des 4 `<audio>`
  (`syncStemMediaState` sur la cible `stemDesiredGains`) — un stem audible ne reste JAMAIS
  `el.muted=true` (cause du silence total de A + B au franchissement d'ENTRÉE VOIX) ; le ducking
  orchestral ne pilote que `filter.gain` du peaking [−3, 0] dB ; la bascule B à `vocalStartSeconds`
  n'est plus sautée par les `vocalBridgeSkips` du démarrage (garde-fou cible) et un
  **`[AUDIO-WATCHDOG]`** loggue l'état réel (`muted`/`paused`/`gain`) des 4 stems de A et B à
  chaque ENTRÉE VOIX. **Zéro déclenchement différé (ALC-250)** : le `el.play()`/`seek()` au
  franchissement d'ENTRÉE VOIX est **supprimé** (bloqué par l'autoplay WebView2 ~7 s après le clic)
  — au clic AUTO-MASHUP, A **et** B démarrent dans le **même geste utilisateur**, B étant
  pré-positionnée à `vocalStart − (ostEntry − A.position)` ; seule la **voix de B** (gain 0 pendant
  l'intro) remonte à 1.0 par le **`vocalGateSeconds`** du fondeur de respiration au downbeat d'entrée
  (aucun nouvel appel à `el.play()`). Les vieux `stems_meta.json` au BPM biaisé **×1,25** sont
  automatiquement purgés et réécrits avec le `reference_bpm` quand l'écart dépasse **±12 %** (rejet
  ~1,25 / ~0,80 côté store avant application au deck). **Fiabilisation pérenne (ALC-251)** : le
  lancement AUTO-MASHUP démarre **A et B ensemble** dans le geste (`Promise.all` des `play()`), la
  vocale étant pré-positionnée à `vocalStart − (ostEntry − A.position)` ; le **gate
  `vocalGateSeconds`** ouvre sa voix en **60 ms** pile à ENTRÉE VOIX (aucun `play()`/`seek()`
  différé) ; un cache `stems_meta.json` dont le `bpm` s'écarte de plus de **±12 %** de la référence
  voit son champ écrasé avec le tempo binaire validé (`isStemsTelemetryBpmAcceptable` rejette aussi
  tout ratio ~1,25 / ~0,80 côté store) ; `ALIGNER TEMPO & PHASE` pendant un automate actif cale le
  tempo + le phasage fin (±0.5 beat) en préservant toujours l'offset structurel vocal.
  **Précision percussive & nature musical (ALC-253)** : le calage des grilles est désormais
  **ancré sur les downbeats percussifs** (`first_downbeat_seconds` du stem `drums`, détecté côté
  Rust et purgé/recalculé pour les vieux caches) — `(vocalStart − fdbB)·rate` est un multiple
  entier de **4 mesures** de A : même en anacrouse (levée avant le temps 1), la phrase tombe **pile
  sur le temps 1** du bloc, jamais à contre-temps ; **`ostEntrySeconds` ≤ 8 mesures** après le
  downbeat de A (~14 s au lieu de M33) de sorte que la voix entre dès le premier drop ; les
  `vocalBridgeSkips` sont strictement croissants ; l'utilisateur garde la main avec le **Beat
  Nudge `◄ −1T` / `+1T ►`** qui recale instantanément la platine vocale d'un temps sans couper le
  son.

### 2.4 Système & Onglets complémentaires

- **POWER OFF** (bouton d'extinction) : purge les caches côté frontend puis **ferme proprement**
  l'application Tauri via la commande `exit_app`.
- **Onglet LIBRAIRIE** (`LibraryView.svelte`) : catalogue musical **local et persistant**
  (base **SQLite** `library.db`, backend Rust `library.rs`). On y **archive** les platines A/B,
  **importe récursivement un dossier** (mp3/flac/wav/m4a/ogg analysés en BPM & clé Camelot par le
  moteur MIR), **recherche** instantanément, filtre par compatibilité (**TOUS** / **COMPATIBLE A** /
  **COMPATIBLE B** / **★ DUOS**) et trie (**AFFINITÉ** / **CLÉ** / **TEMPO**). Chaque piste peut être
  **pré-écoutée au casque** (▶/❚❚ via `convertFileSrc`), **chargée** sur la Platine A ou B (badge
  « SUR PLATINE A/B ») ou **retirée** du catalogue (×). La cartouche **Suggestion Mashup** de
  l'Oracle affiche la meilleure association détectée par le matcher (`mashupMatcher.ts`) et permet
  de la **valider en duo ★** ou de l'**envoyer sur la platine libre**. La platine de
  **référence** du calcul (affinité, labels harmoniques, Δ BPM) **suit le filtre actif** :
  `COMPATIBLE B` → Platine B, sinon Platine A (repli si non chargée) ; toute piste **déjà chargée**
  sur une platine (SUR PLATINE A / SUR PLATINE B) n'obtient plus de **score d'affinité**, est
  **classée en bas de liste** et est **exclue** des compteurs et listes filtrées **COMPATIBLE A/B**
  et de l'**Oracle** (aucune auto-association) pour ne jamais gonfler les vrais partenaires. La
  détection repose sur **`isSameTrack(lib, deck)`** : `filePath` normalisé (`\`→`/`, minuscules,
  espaces retirés) ou, en repli, titre ET artiste normalisés. La cartouche
  Oracle propose **« CHARGER LE DUO → A & B »** à platines vides (sinon envoi sur la platine libre) ;
  la pré-écoute gagne une **barre dorée de scrubbing** et un **volume casque** dédié ; le **liseré du
  badge CLÉ** est coloré selon la compatibilité (émeraude A / bleu B / doré relatif) et des **pochettes
  miniatures** (28×28, encadrées laiton) s'affichent quand disponibles ; le **GENRE** et le **TITRE**
  sont **éditables en double-clic** (commande IPC `library_update_track_meta`) et un bouton discret
  **« EXPORTER SET »** (`.m3u`/`.txt`) exporte la setlist des duos validés. Défilement interne
  `overflow-y-auto`, `h-screen overflow-hidden` préservé. **Édition manuelle des tags (ALC-232)** :
  un bouton crayon `edit` (icône Material, colonne ACTIONS élargie de 110 px à 132 px) ouvre une
  modale *Venezia 1889* centrée pour corriger **Titre, Artiste, Genre** (suggestions `Pop`, `Rock`,
  `House`, `Electro`, `Synthpop`, `Hip-Hop`, `R&B`, `Funk`, `OST / Cinéma`, `Trance`), **BPM** (plage
  DJ 40–240, boutons rapides **÷2 / ×2** contre les erreurs d'octave rythmique) et **Clé Camelot**
  (select 24 clés `1A`–`12B` avec équivalent tonal lisible, table officielle du projet), avec la case
  **« Écrire aussi dans les tags du fichier audio (ID3 / Vorbis / MP4) »** (cochée par défaut).
  La sauvegarde est atomique en SQLite et réécrit les frames embarquées via `lofty` (best-effort) ; la
  piste est **remplacée immédiatement** dans l'affichage (les scores d'affinité mashup, les filtres
  `COMPATIBLE A / B`, l'Oracle Acoustique et les Pistes Ponts se recalculent instantanément via
  `$derived`) et les métadonnées de la platine A ou B sont synchronisées si elle porte la piste
  (`isSameTrack`). **Correctif bidirectionnel (ALC-234)** : la synchronisation couvre aussi
  `baseBpm` (BPM effectif recalculé avec le `pitchPercent` courant) et `camelotLabel` (dérivé de la
  clé via la table `CAMELOT_LABELS`) ; au **chargement sur une platine**, les métadonnées éditées en
  Librairie sont appliquées **en priorité** sur les tags bruts du fichier (cache Store
  `libraryTracks`), ce qui corrige les `.wav` privés de tags ID3. Pour un fichier `.wav`, la case
  « Écrire aussi dans les tags du fichier audio » est **désactivée** dans la modale (mention
  *« Format WAV : métadonnées sauvegardées dans la base AlcheMix II (tags ID3 non supportés par WAV) »*)
  et la réécriture `lofty` est ignorée côté Rust.
- **Favicon / icônes** : monogramme vectoriel AlcheMix II intégré à l'application et au bureau.
- **AUTO-MIX (Crossfader assisté & Bass-Swap automatique)** : bloc horlogère sur la barre du
  Crossfader Master — sélecteur **8 MES / 16 MES**, bouton directionnel intelligent (**⇄ AUTO-MIX → B**
  côté A, **⇄ AUTO-MIX → A** côté B), **STOP** et **jauge de progression**. `startAutoMix(bars,
  direction)` calcule la durée **T = bars × 4 × 60 / BPM effectif** (repli à 120 BPM) puis, à **60 fps**,
  déplace le Crossfader Master vers la platine cible, exécute un **Bass-Swap** progressif sur les
  LOW EQ 120 Hz (grave sortant → −20 dB à mi-parcours, grave entrant → 0.0 dB, restauration après
  coupe du volume) et **glisse le pitch** de la platine entrante vers le tempo maître (1re moitié) si
  l'écart ≤ 6 %. Toute saisie manuelle du crossfader ou d'un LOW EQ appelle **`cancelAutoMix()`** immédiatement.
- **Pistes Ponts locales (Harmonic Bridge Finder)** : lorsque les platines A et B ont un écart
  harmonique **≥ 2 quintes** ou rythmique **> 8 %**, l'Oracle Acoustique affiche **en priorité** les
  meilleures pistes PONT issues de la **Librairie SQLite locale** (`findLocalBridgeTracks` : pivot
  harmonique 55 % + palier tempo 35 % + bonus duo 10 %, hors pistes déjà chargées), avec badge
  **LIBRAIRIE LOCALE**, score %, clé pivot et BPM, et actions **▶** (pré-écoute locale), **→ A / → B**
  (chargement + transition) ; le repli Deezer est conservé. La Librairie affiche aussi un cartouche
  **PONT A↔B** avec bouton **CHARGER PONT** pour débloquer la transition en un clic.

## 3. Spécifications Techniques — Comment c'est codé

### 3.1 Chaîne audio WebAudio (`src/lib/audio/player.ts`)

Chaque platine possède sa propre instance `Player` (un canal audio isolé).

- **Chargement sécurisé** : le frontend demande les **octets bruts** du fichier à Rust
  (`read_audio_file_bytes`) puis les charge en **URL `blob:`**. Cette astuce évite le blocage CORS
  de la WebView sur le protocole `asset://`. L'URL est **révoquée** (`URL.revokeObjectURL`) à
  l'éjection ou au rechargement pour éviter les fuites mémoire.
- **Routage nodal** :

```
  MediaElementAudioSourceNode  (lecture du <audio>)
        │
        ▼
  BiquadFilterNode  LOW  (lowshelf 120 Hz)   ← curseur LOW EQ
        │
        ▼
  BiquadFilterNode  MID  (peaking 900 Hz)    ← Smart Filter (atténuation automatique)
        ▼
  BiquadFilterNode  HIGH (highshelf 3.2 kHz) ← curseur HIGH EQ
        │
        ▼
  GainNode  (gain = volume canal × crossfader puissance égale)
        │
        ▼
  AnalyserNode  (mesure temps réel → galvanomètre)
        │
        ▼
  ctx.destination  (haut-parleurs)
```

- **Sans clic ni latence** : les changements de gain/filtre utilisent des rampes temporelles
  (`setTargetAtTime` / `setValueAtTime`). L'`AudioContext` est réveillé au clic sur PLAY (règle
  des navigateurs : le son doit démarrer sur un geste utilisateur).
- **Rendu 60 fps** : l'animation (bobines, galvanomètres, aiguille Beatgrid) est pilotée par
  `requestAnimationFrame`, découplée du cycle de rendu DOM de Svelte pour éviter tout ralentissement.
- **Moteur stems Key-Lock natif (ALC-246)** : en navigateur, chaque stem (vocals/drums/bass/other)
  joue via un **`<audio>` dédié** (`preservesPitch`/`webkitPreservesPitch`/`mozPreservesPitch = true`,
  `playbackRate` = celui du canal) routé par `createMediaElementSource` → GainNode du stem → chaîne EQ —
  jusqu'à ±10 % de tempo, **hauteur et timbre 100 % d'origine** (zéro effet hélium, zéro glissement
  Camelot). Les 4 éléments sont synchronisés au démarrage/seek/pause et la **dérive > 12 ms** est
  recalée dans le ticker ; `disposeStems` révoque les URLs blob. **Repli** : si le DOM
  (`Audio`/`createMediaElementSource`) est indisponible (tests Node), la lecture via
  `AudioBufferSourceNode` est conservée à l'identique.

> **Runes Svelte 5** : la nouvelle syntaxe de Svelte pour la réactivité. `$state` déclare une
> variable réactive ; `$derived` calcule une valeur dérivée automatiquement ; `$effect` exécute
> du code quand ses dépendances changent ; `$state.raw` stocke une valeur **sans proxy profond**
> (idéal pour de grands tableaux d'échantillons, voir 3.2, pour rester rapide).

### 3.2 Moteur d'analyse musicale Rust (`src-tauri/src/audio.rs`)

L'analyse est lancée **hors du thread principal IPC** (`tokio::task::spawn_blocking`) pour ne
jamais bloquer l'interface.

| Étape | Technique détaillée |
|---|---|
| **Décodage** | Symphonia décode tout format supporté, réduit en **mono 48 kHz** (« monophonie » : mélange des canaux gauche/droit en un seul). |
| **Référence de calcul** | FFT **4096** sur **48 kHz** (≈11.7 Hz par bac) + saut (hop) **1024** (≈21 ms) — compromis précision/CPU documenté (ALC-008). |
| **Tempo (BPM)** | Rééchantillonnage 8 kHz → **STFT** (spectrogramme temporel) → **onsets sub-basses kick** (40–126 Hz) → **peigne gaussien CONTINU multi-fenêtres** : fenêtres 10 s filtrées < 35 % médiane (et **saut des 25 % initiaux** si intro ambiante < 50 % de la médiane, ALC-158), noyau gaussien **σ_t=0.022 s** aligné sur `t_k = φ + k·60/bpm` (temps **flottants**), **peigne Coarse-to-Fine (ALC-159)** : scan grossier [75–155] pas 1.0 BPM → top 3 → raffinement pas 0.1 sur ±2,5, **rejet des sous-harmoniques 2/3** (comb_parity + comparaison B vs 1.5·B ≥ 88 % et parité suspecte → 1.5·B) → agrégation **KDE σ=0.6** → BPM global exact. **ALC-160 — normalisation par DENSITÉ : score = moyenne par battement THÉORIQUE `N = durée_fenêtre / T`** (plus jamais de somme brute sur la fenêtre fixe → un peigne à 98 BPM n'a aucun avantage numérique sur 91 BPM) **+ pénalité de HORS-PHASE** (`0.35 × énergie_moyenne(t_k + T/2)`, vallées entre temps) → score maximal au vrai tempo 91.0 (> 96.5/98/99). **ALC-158 — interpolation linéaire continue de l'autocorrélation** : helper `interp_autocorr` (Pearson à lag RÉEL entre `r[floor]`/`r[ceil]`) branché sur `tempo_autocorr` (peigne binaire continu `1.0r(b)+0.45r(2b)+0.35r(b/2)−0.30r(1.5b)`, [75–155] pas 0.1 + interp parabolique du sommet). **DP linéaire O(N) (ALC-159)** : prédécesseurs **bornés [0.5·period .. 2.0·period]**, période réelle `period_f` + beats sub-trame `refine_beat_pos` → BPM continu. **ZONE CENTRALE active (ALC-159)** : piste > 110 s → 90 s centrales (−20 % intro / −15 % outro) pour le BPM ; tests synthétiques 4/4 purs à **123 / 121 / 91 BPM** précis ≤ ±1,0. (ALC-152 → 160, 258). |

La ZONE CENTRALE 90 s ne sert qu'au BPM. (ALC-151 → 160). **ALC-241 — précision accordage & fondamentale grave** : `estimate_tuning` documente la convention de signe (déviation **> 0 = diapason HAUT** → **soustraction** `(midi − tuning)` dans HPCP/basse pour ramener un *Mi* +35 cents sur sa case tempérée, jamais vers *Fa*) ; `bass_chroma` descend à **55 Hz** et `detect_key_from` renforce le registre grave (combo **0.22**, boost tonique **0.55**, tierces **0.48**) pour départager deux candidats distants d'**1 demi-ton** — ex. Modjo *Lady (Hear Me Tonight)* correctement en **9A / Mi mineur**, plus jamais **4A / Fa mineur**. **ALC-258 — bornage STRICT de la correction d'accordage à ±35 cents** (clamp `±0,2 demi-ton` = **±20 cents** ⊆ ±35) : une dérive d'un demi-ton entier (ex. *Around the World* `8A → 3A`) est impossible ; `library_reanalyze_analysis` (Tauri) ré-analyse BPM/Clé des pistes archivées **dont `user_edited = 0`** uniquement, pour purger les anciennes valeurs fausses sans écraser les corrections manuelles de l'utilisateur (ALC-232). |
| **Arbitrage hybride** | La clé DSP locale est **recoupée** avec les références **AcousticBrainz / MusicBrainz** : consensus, voisinage ou divergence → clé arbitrée + indicateur d'origine. |

> **STFT** : *Short-Time Fourier Transform*, « transformée de Fourier à court terme ». Elle
> découpe le signal en courtes fenêtres temporelles et calcule les fréquences contenues dans
> chacune — le son devient une « image » (temps × fréquence).
>
> **HPCP** : *Harmonic Pitch Class Profile*, un profil harmonique qui compte l'énergie de chaque
> note dans la piste, utilisé pour décider de la tonalité.

### 3.4 Outillage développeur — CodeGraph (pré-index du graphe de code)

**CodeGraph** (`@colbymchenry/codegraph`, licence MIT, **100 % local**) pré-indexe le graphe de
code d'AlcheMix II dans une base SQLite `.codegraph/codegraph.db` (ignorée par Git), couvrant le
pont complet **Svelte/TypeScript ↔ IPC Tauri ↔ Rust** pour réduire drastiquement les tokens
d'exploration par l'agent développeur.

- **Indexation** : `codegraph init --yes` à la racine (ou `codegraph index` pour reconstruire),
  resynchronisation incrémentale `codegraph sync`, état `codegraph status`. Backend de stockage
  **`node:sqlite` natif (full WAL)**. Installé globalement (`npm install -g
  @colbymchenry/codegraph`). Sur Windows, le binaire est trouvé via `$env:Path += ';' +
  (npm prefix -g)`.
- **Requêtes** : `codegraph query "<terme>"` (recherche d'un symbole) ; `codegraph explore
  "<sujet>"` (symboles + chemins d'appel + source en une passe) ; **analyse d'impact**
  `codegraph impact <symbole>` et appelants/appelés `codegraph callers`/`callees <symbole>`
  (critique avant tout changement sur `Player`, `mixerStore`, `audio.rs`, `stems.rs`) ;
  `codegraph affected` (tests impactés) ; `codegraph context` (contexte pour une tâche).
- **Intégration agent** : skill locale `.agents/skills/codegraph/SKILL.md` ; directive
  `.clinerules/05` (interroger le graphe AVANT de multiplier `read_file`/`grep`) ; serveur MCP
  Cline `codegraph serve --mcp` (auto-sync temps réel par file watcher) dans
  `cline_mcp_settings.json`.
- **Preuve IPC** : `codegraph callers load_audio_file` résout la fonction Rust
  `load_audio_file` (`src-tauri/src/commands/mod.rs`) et le vis-à-vis frontend `loadAudioFile`
  (`src/lib/ipc/client.ts`) — le pont Svelte↔Rust est correctement indexé.

**Flux d'exploration frugal recommandé** : `codegraph_explore`/`explore` sur le sujet d'un ticket
→ `codegraph impact`/`callers` sur les symboles critiques → lectures ciblées uniquement sur les
fichiers réellement concernés → `codegraph affected` avant le passage des tests.
